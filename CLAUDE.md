# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Build documentation for a lofted twin bed in a child's room (131" × 186", 8' ceiling, second floor). Not a software project. The user is an experienced builder with full tool access and a flexible budget. The design is essentially finalized; the remaining work is closing the open findings, then the materials list and cut list.

Read `archive/KICKOFF.md` for the original brief (historical; its file names predate Rev U), `AGENTS.md` for when to use subagents, and `audits/` for past review findings.

## Source of truth and workflow

**`dimensions.yaml` is the model.** Every member's framing extents in x (from the window wall), y (from the bed wall), z (above floor), plus every claimed structural connection. The drawing site in `site/` is a *rendering* of it and is subordinate to it. Where they disagree, the yaml wins — unless the yaml mis-encoded the design, in which case fix the yaml and say so.

**`python3 verify.py`** recomputes every derived quantity (schedule table E), checks every connection for real three-axis overlap, hanger engagement, and fastener path, and finds volume clashes. It exits non-zero on any FAIL.

**`python3 build.py`** renders `site/` from the yaml: five scrolling pages — `index.html` (Overview: conventions, locked dimensions, Drawings 1–2), `stairs.html` (Drawings 4, 5, 8, 9), `loft.html` (Drawings 3, 6, 7), `open.html` (the open-items checklist, one card per group), `appendix.html` (schedule, structure, revisions) — plus standalone figures in `site/figs/<key>.svg` and `manifest.json`. Drawing numbers are unchanged; `PAGE_SHEETS` in `drawings/site.py` says which page a sheet is on. It always rebuilds everything (under a second) and **reports which figures changed and which labels moved**. `--single out.html` also writes the whole set as one file, for publishing or printing only.

**`python3 build2.py`** renders `site-v2/` — the drawing set being built to replace `site/`. Every figure in it is projected from the CAD solids rather than from hand-listed members, and every piece is a separately switchable group. See "The v2 drawing set" below.

**The hook does all three for you.** A PostToolUse hook (`tools/hook.sh`) runs on every Write/Edit: editing `dimensions.yaml` or `verify.py` runs verify (FAIL/WARN lines come back to you) and then both builds; editing `drawings/` or `cad/` runs both; `content/` runs the v1 build; `sheets/` runs the v2 build. The one-line change report is injected into your context. You should rarely need to run any of them by hand.

**`/design-change` is that loop as a skill** (`.claude/skills/design-change/SKILL.md`) — the read budget per kind of edit, the gates in order, and which auditor is worth its tokens. Invoke it for any change to `dimensions.yaml`, `drawings/`, `content/` or `cad/`.

The loop for any change:

1. Change `dimensions.yaml` (member extents, connections, `expected:` values). Read the hook's verify output. Fix until clean, or explain to the user why a FAIL is accepted (verify is currently 0 FAIL, 0 WARN).
2. Read the hook's build report. Look **only** at the figures it names — open `site/figs/<key>.svg`, or screenshot them. Do not read the whole site.
3. If a label or caption needs to move, edit that sheet's module in `drawings/`; if prose needs to change, edit `content/`. The hook rebuilds.
4. Bump `rev:` in the yaml and add a row at the top of `content/revisions.json`. One letter per design change; `.1` suffixes for drawing-only cleanups. Update the cut list / materials list to match once they exist.
5. Before cutting material: run `drawing-auditor` and `connection-checker` (see `AGENTS.md`), scoped to the sheets the build reports changed.

Never hand-edit anything in `site/`. It is overwritten on every build.

## Token discipline

The restructure exists so that a change touches a few small files, not one big one. Keep it that way:

- **To change one drawing**, read only `drawings/d<N>_*.py` (20–60 lines) and, if you need a helper, the header of `drawings/model.py`. Geometry comes from the yaml; the module holds only view setup, which members to draw, labels, and its caption.
- **To check a drawing**, read `site/figs/<key>.svg` (6–10 KB) or screenshot it — never a whole page unless you need its captions, and never a `--single` file. Captions live in the sheet module.
- **To change prose** (structure table, open items, conventions, revisions), edit `content/`. Model values go in as `{placeholders}` from `drawings.model.VALS`; an unknown name fails the build. **Quote the model for every dimension** — `{m:rear_ledger.size.x}` and `{m:beam.z0}` read any member's extents straight off it, so prose does not need a named entry per number. What stays literal is deliberate: nominal stock and hardware names, stated design constants, historical parentheticals, and the hand-computed load figures (psi, lb, psf, deflection) — nothing derives those, so re-check them by hand when a member they depend on moves. Hand-typed numbers in prose and labels are the one thing that can still drift — `python3 tools/literals.py d4 d8` lists them with file:line so you check those, not everything.
- **Don't re-render to see what changed.** The build report already says which figures changed and which labels moved. Trust it; the same code produces the site and the report.
- Sheets are numbered by their module name (`d4_stair_section.py` → Drawing 4). Add a sheet by adding a module with `NUMBER`, `TITLE`, `FIGURES`, `CAPTION`, appending it to `SHEET_MODULES` in `drawings/site.py`, and placing it in `PAGE_SHEETS` (the build asserts every sheet is on exactly one page).

## The v2 drawing set (`sheets/` → `site-v2/`)

Being built alongside the Rev-U set, not instead of it: `drawings/` and `site/` stay live and untouched until v2 covers everything, then v1 goes to `archive/`. Four decisions hold it up, and none of them should be relitigated casually:

- **Geometry comes from the solids, per piece.** `cad/view3d.py` answers "what shape is this solid from here" — the front faces projected (`faces()`), and those faces fused into the piece's silhouette (`outline()`), plus `cut_loops()` on a section plane. Nothing is a hand-projected box: a notched stringer comes back as its real 17-point profile because the kernel fused it, not because a sheet knew about the notch.
- **Toggles work because every piece is drawn whole, in depth order.** Hiding a component removes its groups and what stood behind it is still complete. A hidden-line pass would have to be re-run per switch combination; this composites in the browser instead. The cost is that "hidden" lines exist only where a sheet asks for them (an `outline` or `ghost` mode), which is also exactly what the overlays wanted.
- **Consistency is structural, not per-sheet.** `sheets/canvas.py` knows which model axis is across the page and which is up it, so `shell()` draws every wall, the floor and the ceiling the same way on every sheet, wherever the frame runs past a room boundary. Dimensions are placed by SIDE and LEVEL — `dim_h(a, b, "bottom", 0, …)` — and land outside the drawing box by construction, which is the rule d8a and d8b broke in v1. Margins are computed from the levels used; no sheet carries a hand-tuned margin.
- **A detail asks for a slab.** `ViewSpec(cut=…, depth=…)` keeps only a few inches beyond the cut plane. Without it a section at the beam's seat draws every joist, block and rail between the plane and the far wall on top of each other and the joint disappears.

Ten pages: four of drawings (Overview 1–3 · Stairs & nook 4–6 · Half wall 7, 12 · Loft & screen 8–11) and six of reference (Open items · Cut list · Schedule · Fasteners · Appendix · Revisions). The reference pages render through the **Rev U card builders** in `drawings/site.py` rather than a second copy of them, so `content/` stays the single source for both sets; only the CSS is native to v2. The Cut list page is the one exception — v1 has no equivalent — and it renders through `sheets/cutlist.py` from `takeoff()`, the same call the workbook writes from. "The design in one line" sits at the foot of the Overview. Sheets 1–12: iso overview, front elevation, floor plan · stair section, stair framing plan, tread/riser detail · half-wall framing, loft-face panel layout · loft section, loft framing plan, beam-end bearing detail, boxed-ledge detail. `sheets/taxonomy.py` assigns every solid a component and a layer and asserts the assignment is complete, so a member added to the yaml cannot land in no layer. Layer is a drawing concern and lives there, not in the yaml.

**Electrical is the one layer that is not solids** (Rev BC). A device is a point on a named member's face plus the box behind it — `electrical:` in the yaml — so it never goes through `sheets/geometry.py`; `sheets/electrical.py` projects it and draws a symbol carrying the same `data-c`/`data-l` attributes a solid would, and it switches with everything else. Both the drawings and `verify.py` read it through one adapter, `verify.electrical_devices()`, which also folds in the three lights that stay in `loft_lighting:` (the Rev U Drawing 1 still reads that block, and a position written down twice is a position that drifts). `check_electrical` then asks the three things that actually go wrong: is the device on the face it claims, is a `centred` one really centred, and does its box hit anything it did not declare in `lets_into`. The one deliberate exception is a **canless** fixture, which has no housing and may straddle a joist — those are reported with the member and the depth rather than failed, because Rev AP chose true geometric centres knowing it. **Views are cached in `.kernel-cache` like v1's cuts** — a label edit rebuilds in 0.03 s; moving geometry misses and runs the kernel (~4 s).

Two invariants are asserted on every build, both because they failed silently once. **No page may have duplicate element ids** (`check_ids`): every figure is a separate `<svg>` in one document, so their `<defs>` share an id namespace and `url(#box)` resolves to the FIRST match — which clipped seven figures to another figure's frame before anyone spotted the drawings losing their right-hand side. Ids are numbered per canvas. And `python3 tools/labels.py` boxes every label the way the browser lays it out and reports pairs that overlap; it is currently 0, and it is the only check on the one thing in this set still placed by hand.

Still owed on v2: a conventions page, and the electrical layer beyond the devices placed at Rev BC.

## Coordinate and encoding conventions

- Inches, decimal in the yaml. `verify.py` prints nearest-sixteenth alongside; `fr()` formats sixteenths or two decimals.
- Extents are **framing** extents (actual lumber size). Finished faces (wrap, sheathing, ply) are their own members. Cut lists use the framing numbers; layout marks use the finished ones.
- Repeated members use `repeat:`; ids become `id[0]…`. Wildcards in connections are quoted: `"deck_joist[*]"`.
- Stringers are `kind: stringer`; their bbox is ignored and the true sloped profile is computed from `stair:`.
- A row may carry `part_of: <id>` — a notch remnant, one board with its parent on the bench (`beam_tongue`, `deck_joist_tail`). `check_sections` checks it against the stock it was cut from; `NOTCHED` in `cad/model.py` fuses it into one solid.
- Anything not stated in the drawings and guessed during encoding is marked `ASSUMED` in a `note:`. Resolve these with the user, don't silently keep them.
- **Electrical devices are points, not boxes.** `electrical.devices[]` gives each one an `at: [x, y, z]` on a named `host` member, a `face` (the direction it LOOKS: `-z` for a ceiling light, `+z` for an outlet in the ledge lid, `-x` for a switch on the half wall's loft face), and a `box: [w, h, depth]` whose depth runs into the wall behind that face. `lets_into` names every member the box is cut into, and `verify.py` fails any intersection that is not declared.
- `expected:` holds the values Rev T states. When a change legitimately moves one, update it deliberately — that's the audit trail.
- View conventions (stated on the index page): plans bed-wall-up, window wall left; x–z views look toward the bed wall; y–z views keep the bed wall on the left, mirrored where needed.
- **The yaml's axes are LEFT-handed as they map onto the room, and that is load-bearing.** Facing the closet wall (+y), the window wall (x = 0) is on your RIGHT — so yaml +x runs to your left and `x × y = −z`. The naming is consistent from the other vantage: facing the BED wall, +x really is on your right, which is how the sheets are read. This is harmless in 2D — every figure maps two yaml axes onto the page and all twelve come out correct (plans are true from-above plans; d4's half-wall really is in front of the cut; d8b really does look toward the bed wall). It is **not** harmless for a solid: feeding these coordinates straight into a CAD kernel builds the mirror image of the room. `cad/export.py:to_room_frame()` mirrors x into a right-handed room frame (`X = room.x − x`, from the stair/door wall toward the window) for STEP and STL only. Everything else stays in yaml coordinates. Do not "fix" the drawings' mirroring — it is what makes them right. The export is **Z-up**, the CAD standard; some previewers assume Y-up and will show it lying on its back — rotate in the viewer, don't change the export. **Units are declared, not assumed:** the kernel is unitless and OCCT's unit is a millimetre, so STEP is written with `unit=Unit.IN` *and* `write.step.unit = INCH` (inch numbers in the file, declared as inches — set the controllers up first or `export_step` resets it on the session's first call), while STL, which carries no unit and is read as mm by everything, is scaled ×25.4. Both then open at true size.

## Working rules (hard-won — do not relitigate)

- **Never assert a geometric relationship from memory. Compute it.** If it isn't in `verify.py`'s output, it isn't verified.
- **Distinguish framing from finished everywhere.** Platform 50¾" finished / 50" framed. Half-wall 5" finished / 3½" studs. Deck 107" finished / 106¼" structural rim.
- **Errors cluster where two assemblies meet.** Before claiming two members connect, they must be in `connections:` and pass. A connection whose fastener is UNSPECIFIED is not done.
- **Some depths are set by connection requirements, not load.** The nook header is a 2×10 sandwich at ~140 psi because the landing rim needs 7½" to hang from. Never "optimise" a member down without re-running the connection it exists for.
- **Fastener penetration counts what it passes through.** A 1½" hanger nail through ¾" sheathing reaches ¾". Hanger flange holes below the supporting member's bottom hit air.
- **Flag now-or-never decisions** — things that get much harder after a prior step (nook power before sheathing; joist location before the screen top plate).
- **Outside-run dimension lines go outside the wall they measure**, clear of the wall rect, the way d3 and d7 place them — not on or inside the wall face. d8a and d8b currently violate this (noted inline at their `dim_h` calls); fix opportunistically when touching those sheets. If this keeps recurring across sheets, bake the clearance into `dim_h`/`dim_v` in `drawings/svgview.py` instead of relying on each sheet module to get it right.
- **Push back on the user.** The design improved every time a session did.
- **Never commit unprompted.** Make the change, say what changed, and stop. Suggest a commit when it makes sense; the user gives the command. This includes `--amend` and `revert`.
- **Keep replies concise.** No long responses. State the error/update plainly, make the fix, name what changed. The detailed reasoning belongs in the commit message and in `audits/`, not in chat — the user asks when they want more.
- **Design and geometry changes happen inline, with the full model in context.** Subagents audit; they don't design.

## Model choice

The user does not want Fable for everything. Guidance:
- Inline design work, yaml edits, drawing/label updates, prose, cut/materials lists: the session's default model is fine, because `verify.py` and the build report are the safety net.
- `drawing-auditor` is pinned to Opus: it runs rarely (per rev, pre-cut), and a miss costs lumber. Scope it to changed sheets so the cost stays small. Revisit if Fable becomes reliably available again — the point is spending more on a rare, high-stakes check, not the specific model.)

## Files

- `dimensions.yaml` — the model. Edit this.
- `build2.py` — renders `site-v2/`. Thin CLI over `sheets.site`; `--quiet` for the hook.
- `takeoff.py` — the materials takeoff: every solid the kernel says gets cut, packed into boards and nested onto 4×8 sheets, plus the hardware tally. Shared, so the workbook and the v2 Cut list page cannot disagree; cached in `.kernel-cache` the way the views are, and it imports build123d only on a miss. `tools/materials.py` is the xlsx writer over it and `sheets/cutlist.py` is the page.
- `sheets/` — the v2 generator. `taxonomy.py` (component + layer per solid, with a coverage assert), `geometry.py` (`ViewSpec` → per-piece faces / outline / cut / near, cached), `canvas.py` (the drawing surface: room shell, gutter dimensions, label leaders, 3D helpers), `render.py` (records → one `<g>` per piece, painter-ordered), `electrical.py` (the devices, which are symbols rather than solids), `style.py` (the palette, shared by the CSS and the axonometric shader), `sheet.py` (what a sheet module is), `s1_…`–`s12_…` one sheet each, `cutlist.py` (the Cut list page: every sheet of the nest as its own figure at true size, tiled into a keyboard-navigable lightbox, plus the takeoff tables), `site.py` (pages, switch board, print CSS).
- `site-v2/` — the generated v2 set. **Never hand-edit.**
- `verify.py` — the checker. Don't "fix" a failure by editing the checker. `compute_derived()` is shared with the drawings.
- `build.py` — renders `site/` (and `--single`). Thin CLI over `drawings/site.py`.
- `drawings/` — the generator package. `model.py` loads the yaml once and exposes `M`, `ST`, `DER`, constants, `fr()`, `m()`, `R()`, `View`, and `VALS` (named values for prose). `svgview.py` is the orthographic `View` helper (plans, elevations, sections, dimension strings, hatching) that every sheet — and `cad/section.py` — draws through. `d1_floor_plan.py` … `d9_framing_overlay.py` are one sheet each. `schedule.py` is tables A–E and the locked-dimension cards. `site.py` assembles pages, CSS, the manifest, and the change report.
- `content/` — the only hand-written prose: `conventions.yaml`, `structure.yaml`, `open-items.yaml` (a **checklist**: `groups:` of one-line `do:` + optional one-sentence `why:`, plus `closed:` and `summary:` — an item needing a paragraph belongs in the revisions log instead), `revisions.json` (Rev U row first, then Rev T's history).
- `site/` — generated Rev U set, five pages with sticky tabs and ←/→ arrows (buttons and keyboard). **Never hand-edit.** `site/index.html` is where the builder starts.
- `tools/` — `hook.sh` (the PostToolUse hook), `literals.py` (the hand-typed numbers finder), `labels.py` (the overlapping-label finder for site-v2) and `materials.py` (the xlsx workbook, written from `takeoff.py`). Development harness only; nothing here is imported by the build.
- `archive/` — Rev T's hand-drawn set, its yaml encoding (`dimensions-T.yaml`), its revisions log, the original brief (`KICKOFF.md`), the Rev T/U landing sketches (`sketch_T.py`, `sketch_U.py`), the CAD kernel's original spike brief (`CAD-BRIEF.md`), and `dimensions-U.yaml` (a frozen snapshot restored 2026-09-05 so `archive/sketch_U.py` has a real default instead of silently mixing Rev U literals with whatever yaml happens to be passed to it).
- `cad/` — a **derived** build123d kernel layer (`audits/V-kernel-spike.md`). `python3 -m cad` builds the **whole bed** as real solids *from* the yaml — five assemblies (`loft`, `screen`, `stair`, `half_wall`, `nook`), 112 solids, ~2.4 s — `model.py` (boxes from framing extents, stringers extruded from `drawings.stringer_pts()`, plus treads/risers/soffit/header laminations the yaml does not carry; `LAMINATIONS` splits one yaml row into plies, `NOTCHED` fuses several yaml rows into the one board they are — the boxed ledge's front rail, notched over the side ledger — and `build()` asserts every yaml member is in `SCOPE`, a notch part, or context), `section.py` (plane cuts + hidden-line removal, emitted in `drawings/svgview.py`'s `View` inch coordinates), `check.py` (solid interference, minimum distance, fastener ray casts), `export.py` (STEP/STL), `__main__.py` (the runner) — and writes `cad-out/`. `build(context=True)` adds the mattress and the room's existing fixtures as measured-against context; they are never drawn or cut, so `build()` leaves them out by default. It is **not** a source of truth and does **not** replace `verify.py`, `drawings/` or `site/`: it answers the three questions boxes cannot (notched stringer volume, what a screw actually passes through, true sections), and it agreed with `verify.py` to five decimals everywhere both could answer. Run it before cutting material, alongside `drawing-auditor` and `connection-checker`. It found the Rev W joinery error, and the loft port independently reproduced both parked FAILs with quantities — the beam's outer 2×10 had **0.00 sq in** on the side ledger and slat[0] sat on ¾ poplar wrap with no beam under it — which is what Rev Z's 50" ledger fixed (13⅞ sq in per ply, and a seat for slat 0). `cad-out/loft.txt` carries the bearing areas, slat gaps, clearances and the list of UNSPECIFIED fasteners the kernel cannot ray-cast yet. **Drawing 4 is generated from it**: `kernel_cut(v, "x", CUT_X, skip=(...))` in `drawings/model.py` asks the plane what it crosses instead of the sheet listing members, and returns closed loops in `View`'s own inch coordinates. Styling defaults by stock (framing hatched, sheet goods plain) and a sheet overrides per member. Every other sheet still uses `R()` box projection, which is exact for axis-aligned members and costs nothing. Installing needs `python3 -m pip install build123d` (~220 MB of OCCT).
  `scope.py` holds `SCOPE`, `CONTEXT` and `NOTCHED` as plain data with no build123d import, so the drawings can ask which assembly a member belongs to without paying three seconds of OCCT — `cad/model.py` imports them straight back, so there is still one list.
  `view3d.py` is the drawing-facing half of the kernel — silhouettes, front faces and cut loops for an arbitrary view direction, which is what `sheets/` is built on — and `frame.py` is the view frame in plain arithmetic, so the sheets can compute the same camera without paying the 3 s OCCT import.
- `cad-out/` — `python3 -m cad` outputs. **Tracked:** `REPORT.md` (the run log), `loft.txt`, `clash.txt`, `fasteners.txt`, `section.txt`, `model.stl` — small, byte-stable run to run, and the evidence the kernel agreed at this rev. Timings are printed but scrubbed from `REPORT.md` for exactly this reason, so **a dirty `cad-out/` in `git status` means the kernel has not been re-run since the model changed** — treat it as a gate, not noise. **Ignored:** `model.step` + `room.step` (~3.9 MB a run) and the diagnostic SVGs; regenerate them instead. Regenerated every run; never hand-edit.
- `.kernel-cache/` — cut results keyed by a hash of every input that can change them (`dimensions.yaml`, `verify.py`, `drawings/model.py`, `cad/*.py`). Importing build123d costs ~3 s against a build that is otherwise 0.06 s, and the hook builds on every edit — so a label or caption change hits the cache and stays at 0.06 s, while touching geometry misses and runs the kernel. Cached output is byte-identical to a live run (verified). `LOFT_KERNEL_NOCACHE=1 python3 build.py` forces a real run; `python3 -m cad` never uses it. Gitignored, safe to delete.
- `audits/` — dated reports from the subagents. Read the latest before starting design work.
- `.claude/skills/design-change/` — the change loop as an invocable skill (`/design-change`).
- `.claude/agents/` — `drawing-auditor`, `connection-checker`, `materials-pricer`. See `AGENTS.md`.
- `.claude/settings.json` — the hook wiring. `/hooks` to inspect or disable.
